## 它是一门什么语言

<!--
衔接第一篇末尾「重新补充自己的 Python 学习过程」—— 动手之前，先认个脸熟。
这一节是热车，不写深。目标是给完全没接触过 Python 的读者一个第一印象；
对作者自己也是把散印象归拢：以前只知道语法，没认真想过这门语言是什么。

要点：
- **动态类型**：变量没有类型，名字指向对象，对象才有类型。
  `a = 10; a = "hello"` —— 同一个名字先后绑到不同类型的对象上
- **面向对象**：不只是「有 class 关键字」—— Python 里一切皆对象，
  数字、字符串、函数、模块，甚至类本身，都是对象
- 解释执行：不需要编译，改完保存再跑就是新的（细节留给「第一行代码」那节）

可以开的玩笑：学 Python 不愁对象，因为 Python 里所有东西都是一个对象。
⚠️ 玩笑点到为止，一句就够，别变成段子手；放在「面向对象」那段末尾最自然

对照：C++ 里 `int a = 10` 的 a 自带类型，类型是编译期概念；
Python 里类型属于对象，运行时才查。这一条下一篇（变量、名字与类型）还会细讲，
这里只建立第一印象，别展开。

⚠️ 这一节最容易写成「Python 简介」百科条目 —— 那是 AI 味最重的地方。

## 第一行代码：两种跑法

<!--
- REPL（交互式解释器）：终端敲 python 回车，直接一行行试
  —— 适合「我就想看看这行会怎样」
- 脚本文件：写进 hello.py，python hello.py
  —— 适合「这段逻辑我要留着」

对照：C++ 是 g++ 编译 → 链接 → 产出可执行文件 → 运行；
Python 是解释器直接读源文件，中间没有「编译产物」这个概念。
⚠️ 由此引出一个真问题：C++ 里「编译不过」拦在运行前，
    Python 里语法错误要跑到那一行才炸 —— 这个差别值得写，后面异常那篇还会回来。

退出 REPL：exit() 或者 Ctrl+Z 再回车（Windows）。

## pip：Python 的包管理器

<!--
- pip 是什么：Python 世界的「应用商店」，装解释器时一起来了
- 常用三条：pip install / pip list / pip uninstall
- ⚠️ 为什么要写 python -m pip install 而不是 pip install：
  保证包装进「当前这个」解释器。机器上完全可以有两个 Python，
  裸 pip 装到哪个全看 PATH 顺序 —— 这是「我明明装了 import 却失败」的头号原因
- 装包报错先看两件事：是不是忘了激活虚拟环境、是不是权限不够

对照：C++ 竞赛基本没用过包管理器（STL 全包，头文件拷来就用）；
工程上有 vcpkg / conan，但思路不一样 —— 这个差别值得写一段。

## 虚拟环境

<!--
**本篇重点，篇幅要给够。**

- 为什么需要：全局只有一份 Python。A 项目依赖某库的 1.0，B 项目要 2.0，
  装在同一份里必有一个跑不起来。虚拟环境就是给每个项目一份独立的 Python
- 建：python -m venv .venv（.venv 是约定俗成的名字，放项目目录里）
- 激活：
  Windows   → .venv\Scripts\activate
  macOS/Linux → source .venv/bin/activate
- ⚠️ 激活成功长什么样：命令行提示符前面出现 (.venv)。
  没有它就是没激活，这时候 pip install 全装到全局去了 ——
  「我明明建了虚拟环境，包怎么还是装到全局」就是这个
- requirements.txt：pip freeze > requirements.txt 导出，
  pip install -r requirements.txt 复现。clone 一个项目第一件事就是这个

对照：C++ 里没有对应物 —— 依赖跟着工程走、编译期一次解决。
Python 把依赖推到了运行时，所以「每个项目一份环境」成了默认操作。
这也是把 venv 当成本篇重点的原因：不懂它，后面所有项目都会互相污染。

查：tutorial/venv.html
-->

## 编辑器：只讲环境相关

<!--
- 两个主流选择：VS Code + Python 扩展；PyCharm 社区版
- ⚠️ 头号坑：编辑器里选错解释器 —— 终端里能跑、编辑器里一片红波浪线，
  99% 是没指向 .venv 里的那个 python
- 怎么选：VS Code 里 Ctrl+Shift+P → Python: Select Interpreter → 选 .venv 那个
- 不展开：格式化、断点调试、代码补全那些是熟练度问题，不是环境问题

对照：C++ 的 IDE 装完就能写，因为编译器和工程是一套；
Python 的编辑器是「另一个进程」，它得先知道去用哪个解释器。
-->
