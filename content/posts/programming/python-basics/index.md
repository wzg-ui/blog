## 缩进与注释：代码怎么排、怎么写注解

<!--
这一节全是「语法层面但和逻辑无关」的东西，合并成一节讲，
因为它们都是**长什么样**的问题，而不是**算什么东西**的问题。

### 缩进是语法，不是风格（第一要点）
- Python 用缩进划分代码块，缩进错了直接 IndentationError
- **C++ 对照**：花括号是语法，缩进只是给人看的；
  Python 缩进本身就是语法 ⇒ 缩进错了编译器不管，运行才炸
- 统一 4 个空格，⚠️ **同一块内不能混用 Tab 和空格**
  （这个报错信息在初学阶段最容易让人卡住，值得写出来）
- 缩进的具体规则（if 体、for 体、函数体）留到「控制流」那节展开，
  这里只强调「缩进 = 块结构」这个概念

### 分号和续行
- 行尾不用分号；`x = 1; y = 2` 合法但不推荐，一行一件事
- 逻辑上不完整的一行可以续写：括号内直接换行，或者行尾 `\`
  （\` 后面不能有空格，很容易踩）
- 括号内换行是常态，C++ 里少见

### 注释
- `#` 行注释
- **`"""..."""` 文档字符串（docstring）不是注释** ——
  它是运行期的一个真对象，`help(obj)` / `obj.__doc__` 能读到
- **C++ 对照**：C++ 的 `/** */` Doxygen 注释要靠工具转，
  运行时拿不到；Python 的 docstring 运行时就在
  ⇒ 推论：写模块/函数说明用 docstring，别用 `#` 堆
- 约定：模块、公开函数、类用 docstring；行内解释用 `#`

### 顺带一句（不展开）
- 第一行 `#!` 是 shebang，Windows 上不起作用，
  提一句就行，别引出「怎么写可执行脚本」的话题

## 变量：名字绑到对象上

<!--
⚠️ 标题不要叫「变量、名字与类型」——「变量」这个词会把读者带回 C++ 的心智模型。
   Python 里没有「变量」这个东西，只有**名字**和**对象**，
   这个区别是后面切片、推导式、默认参数所有坑的地基，值得占一整节。

开头先用上一节的结果接一句：关键字不能当名字，那剩下的名字怎么用？

### 要点
- 不用声明类型，赋值即绑定：`a = 10` 里的 a 不是一个盒子，是一张标签
- 类型属于对象，不属于名字；`type(x)` 问的是「它指向什么」
- 名字可以重新绑到别的类型上（和 C++ 静态类型的差别）
- isinstance() 才是日常该用的那个，type() == T 在有子类时会失效

### 赋值语句本身的几种写法（初学阶段最容易漏）
- 多重赋值：`a = b = 0`（两个名字绑同一个对象）
- 交换不用临时变量：`a, b = b, a` —— C++ 要 `std::swap`，这里直接写
- 解包：`x, y = 1, 2` / `first, *rest = [1, 2, 3, 4]`
- 增量赋值 `x += 1`（行为和 C++ 一致，一句带过）

### ⚠️ 两个必写的坑
- **`b = a` 不是复制**：`a = [1, 2]; b = a; b.append(3)` 之后 a 也变了 ——
  两个名字绑同一个对象。这是「可变与不可变」的伏笔，
  和 C++ 的默认拷贝构造对照，讲清「什么时候会意外共享」
- **名字必须先绑过再用**：NameError 是运行时报的，
  C++ 那边是未定义行为（编译能过、结果随机）⇒ Python 在这里更安全

### 本节末尾接解释执行（上一版那节的归宿）
- 因为没有编译期检查，把整数当字符串用这类错误要执行到那行才炸
- **C++ 对照**：`int a = 10;` 里的 a 自带类型，
  写错类型编译就拦；Python 里是名字指向一个对象，写错要等运行
- ⚠️ 这句要自己论证，别照抄，也别写成「所以 Python 更安全」这种空结论

## 数字与运算符：值怎么算、怎么比

<!--
⚠️ 这一节是后补的「承重墙」。上一版完全没有，
   但「控制流」（要比较和逻辑）、「推导式」（要算表达式）、
   「异常」（要 raise）三节全靠它，读者会一路断链。

目标不是「运算符大全」，而是：**让后面三节能直接用**，
并且只写从 C++ 过来会算错的那几个。

### 数字类型
- int 是**任意精度**，不是 64 位 —— `2**100` 直接算，
  对照 C++ 的 long long / __int128 会溢出
- float 是双精度；`int + float` 自动提升
- complex 只提名字，不展开
- **bool 是 int 的子类** ⇒ `True + True == 2`，可以点一句，
  但别展开讲什么场景下会坑到（那是类型体操，超出入门视角）

### ⚠️ 算术里必写的真差别（这几个写错就真出 bug）
| 写法 | Python | C++ 对照 |
|---|---|---|
| `7 / 2` | **3.5**（永远真除法） | 整数是 3 |
| `7 // 2` | 3（整除） | 对应 C++ 的整数 `/` |
| `-7 % 3` | **2** | C++ 是 -1 |
| `2 ** 3` | 8 | C++ 没有，用 std::pow |
| `2 ^ 3` | 1（**异或**） | 同样是异或，别混 |
| `7 % 3.5` | **0.0**（两边是 float） | C++ 是编译错 |

`/` 这一条尤其要点破：**C++ 里两个 int 相除是整数除法，
Python 里永远是真除法**，从 C++ 过来算个数会直接算错。
`%` 对负数的差异同理，要给一个 `divmod` 的对照写法。
⚠️ float 取模的结果也别凭直觉猜：`7 % 3.5` 是 **0.0**（`7 // 3.5` 才是 2.0）。

### 比较
- `==` / `!=` / `<` / `>` / `<=` / `>=` 和 C++ 一样
- ⚠️ **`=` 是赋值不是等于**，这个所有人都会踩，一句带过即可
- **链式比较**：`0 < x < 10` 合法（`0 < x and x < 10` 的语法糖）——
  C++ 必须写 `&&`，这是 Python 少写一个运算符的地方
- ⚠️ `float` 相等不要写 `==`（精度问题），提一句，别展开

### 逻辑
- `and` / `or` / `not` 是**运算符**，不是语句，可以写进表达式：
  `x > 0 and math.log(x)`
- 短路求值，和 C++ 的 && || 一样
- ⚠️ **`and` / `or` 返回的是操作数本身，不是 bool**：
  `0 or "默认" == "默认"` —— C++ 的 || 一律返回 bool，这里不一样
  `a = b or default_value` 是 Python 的惯用法，值得单独给例子

### 成员与身份
- `x in xs` / `x not in xs` —— 语义和 C++ 没有直接对应物
- `x is y` 比的是**同一个对象**（比 id），`x == y` 比的是**值**
- ⚠️ 字符串、小整数有驻留/缓存，所以 `'a' is 'a'` 可能为 True ——
  说清楚「is 不该拿来做值比较」，别写成「is 完全不能用」

### 真值判断
- `if xs:` / `while s:` 这种写法 C++ 里没有
- 空 list、空 str、空 dict、0、None 都是假；非空对象都是真
- 对照 C++ 里必须写 `if (!s.empty())` / `if (p != nullptr)`

### 运算与自增
- `+=` `-=` `*=` `/=` `//=` 有，`++` / `--` **没有**
- ⚠️ C++ 里 `i++` 是表达式，Python 里是语句 ——
  这在推导式那一节会直接卡住，值得在这里先提一句

### 明确不写
- 位运算（& | ^ ~ << >>）：和 C++ 几乎一样，一句「行为一致，不展开」
- 三元表达式：`A if cond else B`，对照 C++ `cond ? A : B`，放在推导式那节讲更顺
- 三种数字类型的完整转换规则
- 运算符重载（第三篇）

对照：C++ 里同样的事情要么写 lambda + 标准算法，要么写显式运算。
查：tutorial/introduction.html 的数字部分、library/stdtypes.html
-->

## 序列：list 与 tuple

<!--
把原来的「四种基本容器」拆开，这一节只讲序列。
理由：list/tuple 的操作范式是**按位置**（索引、切片、遍历），
和 dict/set 的「按键查找」完全是两套心智，挤在一节里对照会乱。

开头先接「数字与运算符」：那里的 int 只是单个值，
从这里开始讲「一组值怎么装起来」。

### 创建与访问
- list 用 []，tuple 用 ()
- 负索引从后往前数：xs[-1] 是最后一个

### 可变与不可变
- list 可改，tuple 不可改（⚠️ 但 tuple 里放 list 仍然能改「内容」，
  不可变指的是**元素绑定**不能换，这个坑要点破）
- ⚠️ 呼应「变量」那节的 `b = a` 不是复制：改 a 会影响 b，
  这是「可变」真正的麻烦之处
- 查存在：in；改：append / extend / remove / del

### 切片
- [start:stop] 左闭右开，负索引也能进切片
- **切片返回的是新对象，不是视图** —— 这是和 C++ span 最本质的差别
- 三种写法：正着、反着、跳步
- ⚠️ 别写成「切片是引用、修改会改到原列表」，这是常见错结论，记得实测

### 顺手带过（不展开）
- list 乘法 `[0] * n`、`in` 的复杂度是 O(n)（和 C++ 的 find 同级）
- list 是「动态数组」，中间插入是 O(n) —— 一句带过即可

对照：C++ 里 vector 的区间操作要么写循环，要么用 span / 迭代器区间。

查：tutorial/datastructures.html（5. 数据结构）、tutorial/introduction.html 序列部分

<!--
序列之外的另一半。同样是「容器」，但操作范式完全不同，这一节要明显区别于上一节。

- 键值对应 map，但插入是 **O(1)**（哈希表，不是平衡树）
- 键必须是**可哈希**的 ⇒ 这里要提一句 tuple 可以做键、list 不行
