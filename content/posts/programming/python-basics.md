## 名字与绑定：变量到底是什么

<!--
⚠️ 标题不要叫「变量、名字与类型」——「变量」这个词会把读者带回 C++ 的心智模型。
   Python 里没有「变量」这个东西，只有**名字**和**对象**，
   这个区别是后面切片、推导式、默认参数所有坑的地基，值得占一整节。

要点（自己填具体例子）：
- 不用声明类型，赋值即绑定：`a = 10` 里的 a 不是一个盒子，是一张标签
- 类型属于对象，不属于名字；`type(x)` 问的是「它指向什么」
- 名字可以重新绑到别的类型上（和 C++ 静态类型的差别）
- isinstance() 才是日常该用的那个，type() == T 在有子类时会失效
- **C++ 对照**：`int a = 10;` 里的 a 自带类型，Python 里是名字指向一个对象 ——
  这句要自己论证，别照抄

写法上：
- 这一节是全文地基，值得写得最慢
- 配一张「标签贴向对象」的示意图（正文里用代码块画，或者干脆用一句话说清）

查：tutorial/introduction.html 的数字部分、library/stdtypes.html
-->

## 序列：list 与 tuple

<!--
把原来的「四种基本容器」拆开，这一节只讲序列。
理由：list/tuple 的操作范式是**按位置**（索引、切片、遍历），
和 dict/set 的「按键查找」完全是两套心智，挤在一节里对照会乱。

要点：
### 创建与访问
- list 用 []，tuple 用 ()
- 负索引从后往前数：xs[-1] 是最后一个
### 可变与不可变
- list 可改，tuple 不可改（⚠️ 但 tuple 里放 list 仍然能改「内容」，
  不可变指的是**元素绑定**不能换，这个坑要点破）
- 查存在：in；改：append / extend / remove / del
### 切片
- [start:stop] 左闭右开，负索引也能进切片
- **切片返回的是新对象，不是视图** —— 这是和 C++ span 最本质的差别
- 三种写法：正着、反着、跳步
- ⚠️ 别写成「切片是引用、修改会改到原列表」，这是常见错结论，记得实测

对照：C++ 里 vector 的区间操作要么写循环，要么用 span / 迭代器区间。

查：tutorial/datastructures.html（5. 数据结构）、tutorial/introduction.html 序列部分
-->

## 映射与集合：dict 与 set

<!--
序列之外的另一半。同样是「容器」，但操作范式完全不同，这一节要明显区别于上一节。

### dict
- 键值对应 map，但插入是 **O(1)**（哈希表，不是平衡树）
- 键必须是**可哈希**的 ⇒ 这里要提一句 tuple 可以做键、list 不行
- 取不到默认抛 KeyError；dict.get(k, default) 才是日常写法
- 遍历 dict 得到的是**键**，不是键值对（和 C++ 的 structured binding 对照）
- 删除：del / pop / popitem
### set
- 对应 C++ 的 unordered_set，去重 + 成员判定
- 集合运算：| & - ^ （对照 C++ 要手写）

⚠️ 别漏 dict 的**遍历顺序**：Python 3.7+ 保证插入序，
   但这不是「无序表」，和 C++ unordered_map 的直觉相反，值得单独强调一句。

查：tutorial/datastructures.html、library/stdtypes.html
-->

## 字符串：另一种序列

<!--
⚠️ 第一版架构里**完全没有这一节**，是明显缺口 ——
   str 是日常用得最多的类型，只讲容器不讲它说不通。

它同时是「序列」（可以索引、切片、遍历）和「非数字类型」（拼接语义不同），
正好承接前两节：

- 三种写法：'单引号'、"双引号"、'''三引号多行'''
- 索引与切片：和 list 一样是序列
- ⚠️ 字符串**不可变**：s[0] = 'a' 会直接报错
  （C++ 里 std::string 可改，这里必须点破，很多人第一反应是错的）
- 拼接用 +，但别在循环里拼（对照 C++ 也没有这个问题）→ 用 ''.join()
- 最常用的一批方法：strip / split / join / replace / startswith / find
- f-string：f"...{name}..." —— 这是 Python 相对 C++ 最舒服的地方之一，
  单独给一个例子，并对照 C++ 的 std::format / ostringstream

⚠️ 别写成字符串教程，只写「和前面序列那节的关系 + 不可变 + f-string」三件事，
   方法列表挑最常用的几个即可。

## 控制流

<!--
### 分支
- if / elif / else，和 C++ 一样是自上而下第一个成立的分支
  （⚠️ 强调不是「多个独立 if」，这是从 C++ 过来最容易写错的地方）
### 循环
- for 的迭代对象范围比 C++ 广得多：任何可迭代对象（列表、字符串、dict、文件、生成器）
- range(n) 是**惰性**的，不真的产生一个列表（对照 C++ 要真的构造）
- range 的三参数形式和 C++ 不一样：range(1, 10, 2) 不含 10
- while 和 C++ 基本一致
- break / continue 和 C++ 一致
### 循环的 else 子句
- C++ 没有的东西，而且**反直觉**：它是「没被 break 才执行」
- 要写清楚它到底什么时候跑，最好给一个 for-else 找元素的例子
-->

## 推导式：把循环写进表达式

<!--
Python 风格的核心，也是最容易写出「为了用而用」的地方。

### 基本形式
- [f(x) for x in xs]
### 带条件、嵌套
- [f(x) for x in xs if cond]
- 嵌套对应 C++ 的多层循环
### 什么时候不该用
- 逻辑一复杂，推导式就比 for 难读

⚠️ 架构问题（第一版的悬空点）：这里要用到 f(x) 和 lambda，
   但「函数」被划到第三篇 ⇒ 读者在这一节就会断链。

⚠️ 建议顺手提一句生成器表达式（把 [] 换成 ()），
   作为「下一篇讲函数/模块」的钩子，但只提名字，不展开。

对照：C++ 里同样的事情要么写 lambda + 标准算法，要么写显式循环。

## 异常：让错误在可控的地方冒出来

<!--
⚠️ 第一版把异常划给了第三篇，但它是**语句**，属于「流程怎么控制」，
   和本篇定位（值怎么表达 + 流程怎么控制）一致；「代码怎么组织」才归第三篇。

要点：
- try / except / else / finally 四段的分工
  （else 是「没抛异常才执行」，和循环 else 一个套路，可以呼应上一节）
- 捕获具体异常类型，别裸 except —— 呼应「三种基本容器」那节提到的显式风格
- raise 主动抛；raise ... from ... 保留原始原因
- 自定义异常：class MyError(Exception)（只提一句，类放第三篇）

  Python 的惯例是抛，但更鼓励「先问一句」（get / in / hasattr）而不是靠 try 包住

⚠️ 别写成异常教程。目标是：读者看完知道什么时候该抛、什么时候该问、
