## 开场

CACC 还有一个多月，算法从这里开始写。第一篇不讲任何具体算法，讲两件比算法更先的东西：一个是**复杂度**，用来在下笔之前判断这个写法跑不跑得完；一个是**对拍**，用来在交上去之前判断这个写法对不对。后面每一篇都会反复用到这两件事，先把家伙备齐。

## 复杂度：数循环，不数行

一句判据：**O 记号数的是「输入规模变大时，基本运算次数按什么速度长」**，常数倍和低阶项都丢掉。`2n² + 3n + 1` 写成 O(n²)，因为 n 大了以后别的都是零头。

数的是循环，不是行数。同样是十行代码：

```cpp
for (int i = 0; i < n; i++)          // 一层：O(n)
    sum += a[i];

for (int i = 0; i < n; i++)          // 两层嵌套：O(n^2)
    for (int j = 0; j < n; j++)
        sum += a[i] * a[j];
```

常见量级排一排（n = 10⁵ 时各要做的次数）：

| 量级 | 次数 | 一句话 |
|---|---|---|
| O(1) | 1 | 和 n 无关 |
| O(log n) | 17 | 每步砍一半，二分 |
| O(n) | 10⁵ | 扫一遍 |
| O(n log n) | 1.7×10⁶ | 排序的代价 |
| O(n²) | 10¹⁰ | n 上万就危险 |
| O(2ⁿ) | — | n 到 30 就到头 |

## 多快算快：一条换算

一条够用的换算：**10⁸ 次基本运算 ≈ 0.1 ~ 1 秒**。评测时限一般 1 到 2 秒，所以把「时限」换算成「运算次数预算」，再拿它去除 n 的规模，就知道哪个量级能过。

本机实测（g++ -O2，桌面机，比赛机同量级）：

```text
1e8 次加法: 0.12 秒
```

拿 n = 10⁵ 的排序试一下就知道这条换算怎么用。同样的数组，两种排法：

```text
冒泡 n=1e5: 10.13 秒    // O(n²) ≈ 5×10⁹ 次比较，超时没悬念
sort n=1e5: 0.004 秒    // O(n log n) ≈ 1.7×10⁶
```

差了两千五百倍，复杂度差的就是这个。注意冒泡这 10 秒还是编译器帮了忙的结果——`-O2` 下简单的比较交换会被优化，换成更「真实」的 O(n²)（比如内层带取模），只会更慢。

## 数据范围反推算法

竞赛题先看数据范围，因为**出题人给范围就是在告诉你算法**。范围小是请你写暴力，范围大是逼你换更快的量级：

| n 的规模 | 运算次数预算（按 10⁸） | 能接受的量级 |
|---|---|---|
| ≤ 10² | 10⁶ | O(n³) 随便写 |
| ≤ 10⁴ | 10⁸ | O(n²) 是底线 |
| ≤ 10⁵ ~ 10⁶ | 10⁸ | 只剩 O(n log n) 和 O(n) |
| ≥ 10⁸ | 10⁸ | O(log n)、O(1) 数学题 |
| n < 20 左右 | — | 搜索、状压，O(2ⁿ) 专供 |

这是经验口诀不是定理，但可靠性足够高：看到 n ≤ 10⁵ 就别写两层循环，看到 n ≤ 20 就该想起爆搜。

## 对拍：暴力当裁判

复杂度解决「跑不跑得完」，对拍解决「对不对」。思路：写一个**慢但一定对**的暴力，再写一个随机数据生成器，两边跑同样的输入，比输出。跑几百轮都对上，基本就有底气了。

拿「区间求和」做例子，n 个数、m 次询问，输出 `a[l..r]` 的和。对拍要三个文件。

数据生成器，`gen.py`，seed 当参数保证每组数据能复现：

```python
import random, sys
seed = int(sys.argv[1])
random.seed(seed)
n = random.randint(1, 20)
m = random.randint(1, 10)
print(n, m)
print(' '.join(str(random.randint(-100, 100)) for _ in range(n)))
for _ in range(m):
    l = random.randint(1, n); r = random.randint(l, n)
    print(l, r)
```

要验的写法 `main.cpp`，前缀和：

```cpp
#include <cstdio>
int main() {
    int n, m;
    scanf("%d %d", &n, &m);
    static long long s[100005];
    for (int i = 1; i <= n; i++) {
        int x; scanf("%d", &x);
        s[i] = s[i - 1] + x;
    }
    while (m--) {
        int l, r; scanf("%d %d", &l, &r);
        printf("%lld\n", s[r] - s[l - 1]);
    }
    return 0;
}
```

暴力裁判 `brute.cpp`，问一次加一次，O(nm) 慢但一眼对：

```cpp
#include <cstdio>
int main() {
    int n, m;
    scanf("%d %d", &n, &m);
    static int a[100005];
    for (int i = 1; i <= n; i++) scanf("%d", &a[i]);
    while (m--) {
        int l, r; scanf("%d %d", &l, &r);
        long long sum = 0;
        for (int i = l; i <= r; i++) sum += a[i];
        printf("%lld\n", sum);
    }
    return 0;
}
```

跑起来只要一个循环：

```bash
g++ -O2 main.cpp -o main && g++ -O2 brute.cpp -o brute
for i in $(seq 1 1000); do
    python gen.py $i > in.txt
    ./main  < in.txt > out1.txt
    ./brute < in.txt > out2.txt
    diff -q out1.txt out2.txt || { echo "seed $i 不一致"; break; }
done
```

本机实测 50 轮全过，花了 31 秒——开销几乎全在起进程上，数据本身小得很，真正的比赛环境跑一千轮也就几十秒。一旦打出「seed X 不一致」，`in.txt` 就是现成的反例，拿去单步调。

对拍有三类抓不到的错，心里要有数：

1. **答案不唯一**——比如「输出任意一组解」，两边答案都对但文本不同，`diff` 会误报，比较逻辑要专门写
2. **两边一起溢出**——正解和暴力都拿 `int` 存和，一起溢出，输出照样一致；暴力也要用对范围
3. **生成器太温和**——n 永远是 5 到 15，就永远碰不到 n=1 和 n=20 的边界；`gen.py` 里专门留几轮输出极端数据
